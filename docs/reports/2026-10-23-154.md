# Report: Belfast Wheel Development Process

The Belfast Wheel development process is a highly autonomous, multi-bot operation that successfully delivers frequent updates, but is currently throttled by manual "money rule" verification, bot capacity limits, and document-level merge conflicts. While Claude coordinates and Copilot/RolexG build, the transition from "DONE" to "SHIPPED" is often delayed by evidence requirements that could be automated.

## The Team

- **Claude (Coordinator):** Turns Cillian's Banter asks into GitHub issues, runs the fast-sim by default, and maintains the `HANDOFF.md` roadmap.
- **Copilot (Builder):** The primary workhorse for features and refactors. Picks up `copilot-task` issues.
- **RolexG (Rapid Response):** A Gemini agent for small fixes and second opinions. Limited to 8 tasks/day.
- **Gemini (Reviewer):** Automates PR reviews and merges on green CI.
- **The Gambler (Odds Watcher):** An independent auditor that verifies odds on specific `gambler-task` issues.
- **Jimini (Analyst):** Produces read-only reports and documentation (like this one).

## Findings

### 1. Daily Capacity Caps and Inter-Bot Handoffs
Bots have hard daily limits (RolexG: 8 tasks, Copilot: 15 tasks) which frequently halt progress mid-update.
- **Problem:** When RolexG hits its cap (as seen with issue #98 "sound not working"), work stops unless another bot is manually re-assigned.
- **Impact:** Updates that should take 45 minutes can stretch across calendar days.
- **Fix:** Implement a "Delegation Protocol" where a bot hitting its cap automatically pings the next available bot (e.g., RolexG tags Copilot) with a summary of the current state.

### 2. Manual "Money Rule" Evidence Bottleneck
PRs involving stakes or prizes require payback evidence and a Banter notice, which are currently manual steps.
- **Problem:** PR #95 (Update 29) was delayed because the fast-sim comparison produced no result, leading Cillian to waive the rule just to ship. PR #92 was eventually closed after failing to produce valid timing/sim evidence.
- **Impact:** Money PRs (the most sensitive) are the most likely to stall or be shipped with waived safety checks.
- **Fix:** Integrate `tools/sim/fastsim.mjs` directly into the CI pipeline for "money" labelled PRs. The bot should automatically post the before/after payback result as a PR comment.

### 3. Merge Conflicts in HANDOFF.md
`HANDOFF.md` serves as both the long-term roadmap and a real-time status board, leading to constant churn.
- **Problem:** In the Update 25 "Smooth Operator" release, `HANDOFF.md` was edited 25 times in an hour across multiple branches, making it the primary source of merge conflicts.
- **Impact:** Bots waste turns resolving conflicts in a documentation file rather than fixing bugs.
- **Fix:** Move the "NOW" plan to `tracker-plan.json` and use `tools/status.mjs` to generate the view. Bots should update the JSON, which is less prone to conflict than a formatted Markdown list.

### 4. PR "Silent Stalls"
PRs often sit in a "DONE" state but unmerged because no bot is actively monitoring for the next step.
- **Problem:** PR #34 (Smoothness) stalled for 51 minutes during Update 25 because "nobody watched the stalled PR; it was noticed only when Cillian asked."
- **Impact:** Idle time accounts for nearly 50% of some update cycles.
- **Fix:** Add a "Stall Alarm" GitHub Action that pings Banter (#30) if a PR has been green but unmerged (or has no activity) for more than 15 minutes.

### 5. Vague "Feel" Tasks vs. Hard Repros
Tasks based on subjective "feel" (like "sluggishness") often miss the mark without a concrete reproduction.
- **Problem:** Task 9 "Smoothness" was a generic speed checklist that failed to fix the actual "main-wheel freeze" (#49) Cillian was seeing.
- **Impact:** Engineering effort is spent on optimizations that don't improve the user experience.
- **Fix:** Enforce a "Repro First" policy for UX tasks: no task is started without a recording, a specific frame-time target (e.g., < 8ms p95), or an exact reproduction path.

## The 5 Most Valuable Improvements

1. **Automated Money Evidence:** Move fast-sim into CI for money PRs. (Owner: **Copilot**)
2. **JSON Tracker:** Replace the `HANDOFF.md` NOW section with `tracker-plan.json`. (Owner: **Claude**)
3. **Stall Alarms:** Proactive 15-minute pings on Banter for idle PRs. (Owner: **Gemini**)
4. **Auto-Handoff:** Automatic bot-to-bot tagging when daily caps are reached. (Owner: **Claude**)
5. **Hard Repro Policy:** Mandatory recording or metrics for UX/Performance tasks. (Owner: **Cillian**)
