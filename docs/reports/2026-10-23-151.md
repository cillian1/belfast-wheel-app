# PR Review Report: #152 and #165

This is an independent read-only review of two RolexG money PRs into `update-31`. I have analyzed the current codebase to verify the implementation of requested features and fixes.

## Summary

Both PR #152 and PR #165 require changes. The requested fixes in PR #152 for `host.html` are not present in the current file, making balance paths unsafe. The "gamble or collect" feature requested in PR #165 could not be found, so its payback cannot be verified.

---

## PR #152: host.html wallet fixes

**Status: Changes needed**

RolexG claimed to have updated `host.html` to fix the wallet race condition, secure the host PIN, and limit adjustments. However, my review of the `host.html` file shows it is still in its unfixed state.

### 1. Wallet race condition (high)
- **Finding:** The `db.txn` function in `host.html` still contains the logic that disables ETag protection upon any network error or null response.
- **Unsafe Balance Path:** If a host's network blips during a transaction, the safety "tags" are turned off. If two hosts (or a host and a player) then edit the same user balance, one update will be lost. This makes the balance path **unsafe**.
- **Suggested fix:** Sync `db.txn` with the fixed version in `src/wallet/db.js`.

### 2. Host PIN security (high)
- **Finding:** The host PIN hash is still being read from and written to `sessionStorage`.
- **Why it matters:** It survives reloads, violating the "memory-only" requirement.

### 3. Adjustment limit (medium)
- **Finding:** The `adjust` function still has no upper bound.
- **Why it matters:** Risk of large accidental entries.

**Verdict: changes needed**
