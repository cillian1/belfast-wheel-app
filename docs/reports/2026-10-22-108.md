# Codebase Health Report Re-check

This report re-evaluates the findings from the previous health report against the current `main` and `update-31` state, following changes in #110 (wallet) and #112 (sound).

## Summary of Still-Real Problems

The following issues remain in the codebase and should be prioritized:

1.  **High: Race Condition in `host.html` Wallet Update** (`host.html:150-170` approx): The `db.txn` fix from #110 was not applied here. It still falls back to a non-transactional write if an ETag fetch fails once, risking balance corruption during concurrent host actions.
2.  **High: Insecure Host PIN Storage** (`host.html:209`): The host PIN hash is still stored in `sessionStorage`, making it accessible to any script on the page.
3.  **Medium: Aggressive Polling in Banter** (`chat.html:28`): A 3-second poll interval for the entire message list is heavy for old Android phones and GitHub's rate limits.
4.  **Medium: Missing Amount Bounds in Adjustments** (`host.html:387`): The host "adjust" tool has no upper limit, allowing accidental entry of massive balance changes.
5.  **Low: Code Duplication (`<shared>` block)**: The wallet logic is duplicated between `src/wallet/db.js` and `host.html`. This directly led to the inconsistent fix in finding #1.

## Detailed Re-check Results

### 1. High: Potential for Race Conditions in Wallet
*   **Status:** **Still real** in `host.html`.
*   **Analysis:** While PR #110 fixed the `db.txn` logic in `src/wallet/db.js` by ensuring it only falls back if no ETag has ever been seen, the `host.html` file contains a duplicate copy of this logic that was **not** updated.
*   **File:** `host.html` (inside the script block, `db.txn` function).
*   **Reproduction:** Block or fail the first ETag fetch in `host.html`; the code will set `db.tags = false` and proceed with plain read-then-write for all subsequent updates in that session.
*   **Suggested Fix:** Sync the `db.txn` implementation in `host.html` with the one in `src/wallet/db.js`.

### 2. High: Insecure Host PIN Storage
*   **Status:** **Still real**.
*   **Analysis:** The host PIN hash is stored in `sessionStorage` at line 209 (after successful login) and checked at line 192.
*   **File:** `host.html:192, 209`.
*   **Why it matters:** Any XSS vulnerability or malicious script (e.g., from a CDN if one were added) could read this hash and gain full host control.
*   **Suggested Fix:** Require the PIN for sensitive actions (like "Paid" or "Adjust") instead of storing it, or use a more secure short-lived memory-only variable.

### 3. Medium: Lack of Input Validation
*   **Status:** **Still real** (Partially improved).
*   **Analysis:** The `edge` setting now has a 50-120 range check, and `newPin` requires 4+ digits. However, the "Adjust" amount used to gift or fix player balances has no upper bound.
*   **File:** `host.html:387`.
*   **Reproduction:** Enter `1000000` in the Adjust amount; it will be processed without warning.
*   **Suggested Fix:** Add a "Reasonable maximum" check (e.g., €500) to the adjustment tool to prevent typos.

### 4. Medium: Performance on Older Devices
*   **Status:** **Still real**.
*   **Analysis:** `chat.html` polls every 3 seconds. Every poll triggers a full re-render of the message list (`main.innerHTML = html`). On an old phone with a long chat history, this will cause stuttering and high battery drain.
*   **Files:** `chat.html`, `host.html`.
*   **Suggested Fix:** Implement incremental rendering (only add new messages) or virtual scrolling for the chat. Increase the poll interval or use a "pull to refresh" pattern.

### 5. Low: Inconsistent Coding Style
*   **Status:** **Still real**.
*   **Analysis:** The "dense" style is a project convention for phone performance, but the divergence between `src/wallet/` and `host.html` is a maintenance risk.
*   **Suggested Fix:** Consolidate the shared logic into a single source that both the app and host page can include (or that the build tool injects into both).

### 6. Low: Outdated GitHub Actions
*   **Status:** **Fixed**.
*   **Analysis:** `.github/workflows/ci.yml` now uses `actions/checkout@v4`.
