# Codebase Health Report

This report summarizes the findings of a codebase analysis of the Belfast Wheel project. It highlights potential issues and provides recommendations for improvement.

## Summary

The most critical issues discovered are related to the real-money wallet's host page (`host.html`). There is a significant risk of race conditions when updating user balances, potentially leading to incorrect payouts. The host PIN is also stored insecurely in the browser's session storage. Additionally, the report identifies several opportunities to improve the maintainability, performance, and security of the codebase.

## Findings

### 1. High: Potential for Race Conditions in Wallet

- **File:** `host.html:206-220`
- **Certainty:** High
- **Description:** The `db.txn` function in `host.html` implements a read-modify-write pattern to update user balances. However, it falls back to a simple read-then-write if the ETag-based transaction fails. This fallback is vulnerable to race conditions where two concurrent updates can overwrite each other, leading to incorrect balances.
- **Impact:** This could result in players receiving incorrect payouts or their balances not being updated correctly.
- **Suggested Fix:** Remove the fallback to the non-transactional write. If the ETag-based transaction fails, it should be retried until it succeeds or a timeout is reached.

### 2. High: Insecure Host PIN Storage

- **File:** `host.html:252`
- **Certainty:** High
- **Description:** The host PIN is stored in `sessionStorage` after a successful login. `sessionStorage` is not a secure storage mechanism and can be accessed by any script running on the same page.
- **Impact:** A malicious script could steal the host PIN, giving an attacker full control over the host page and the ability to manipulate user balances.
- **Suggested Fix:** The host PIN should not be stored in `sessionStorage`. Instead, the host should be required to enter their PIN for every sensitive action, or a more secure authentication mechanism should be implemented.

### 3. Medium: Lack of Input Validation

- **File:** `host.html:360-362`
- **Certainty:** High
- **Description:** The input fields on the host page have minimal client-side validation. For example, the `edge` input allows any floating-point number, and the `newPin` input does not enforce any complexity requirements.
- **Impact:** This could lead to invalid data being saved to the database, potentially causing errors or unexpected behavior.
- **Suggested Fix:** Implement robust client-side and server-side input validation for all user-provided data.

### 4. Medium: Performance on Older Devices

- **Files:** `host.html`, `chat.html`
- **Certainty:** Medium
- **Description:** Both `host.html` and `chat.html` use a significant amount of JavaScript and have relatively complex DOM structures. The frequent polling in `host.html` and `chat.html` can also contribute to performance issues.
- **Impact:** Older Android phones with limited resources may experience slow performance, unresponsiveness, and high battery drain.
- **Suggested Fix:** Optimize the JavaScript code and simplify the DOM structure where possible. Consider using more efficient event handling and reducing the frequency of polling. For `chat.html`, consider implementing a more efficient way to load and display messages, such as virtual scrolling.

### 5. Low: Inconsistent Coding Style

- **Files:** Various
- **Certainty:** High
- **Description:** The codebase has an inconsistent coding style, with a mix of different formatting and naming conventions.
- **Impact:** This makes the code harder to read and maintain.
- **Suggested Fix:** Adopt a consistent coding style and use a linter (like ESLint) and a code formatter (like Prettier) to enforce it automatically.

### 6. Low: Outdated GitHub Actions

- **File:** `.github/workflows/ci.yml:13`
- **Certainty:** High
- **Description:** The `ci.yml` workflow uses `actions/checkout@v2`, which is outdated.
- **Impact:** Using an outdated action may result in slower builds and a lack of new features and bug fixes.
- **Suggested Fix:** Update all GitHub Actions to their latest versions.
